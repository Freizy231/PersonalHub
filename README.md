# Personal Hub

本地优先的个人学习与生活工作台：任务、日程、笔记、饮食、财务、运动、加密私密库、学习路线、资料库（PDF / EPUB / 网页 / 课程）、项目、技术情报与可选 AI 助手。数据只在本机，服务只监听 `127.0.0.1`。

## 日常使用

```bash
# 首次或升级后构建前端（需要 Node >= 22.12）
cd frontend && npm install && npm run build && cd ..

# 启动并自动在默认浏览器打开本机入口（入口凭据不会输出到终端）
backend/.venv/bin/python -B -m backend.manage serve --data-root runtime/personal-hub --port 8765 --open
```

- 会话为滑动有效期：连续 8 小时无操作才需要重新进入，最长 7 天；服务重启后失效。不加 `--open` 时，到 `runtime/personal-hub/config/launch-8765.url` 取入口，不要分享该地址。
- 数据库需要升级时，页面会提示；先停服务，再按提示执行 `backend.manage upgrade`。升级前会自动备份并在副本上演练。
- `Ctrl K` 跳转页面或搜索资料，`/` 聚焦顶部搜索，`Ctrl Shift N` 记录想法，编辑器里 `Ctrl S` 保存，`?` 查看全部快捷键。

文档入口：[HANDOFF](HANDOFF.md)（当前状态与交接）、[docs/OPERATIONS.md](docs/OPERATIONS.md)（运行、备份、恢复）、[docs/UI_UX_SPEC.md](docs/UI_UX_SPEC.md)（界面规范）、[docs/DEVELOPMENT_RULES.md](docs/DEVELOPMENT_RULES.md)（开发规则）。

## 旧版：Tech Intel Hub（独立的 Streamlit 情报采集工具）

以下内容描述根目录的旧工具（`app.py`、`collector.py`、`db.py`），它与上面的 Personal Hub 相互独立，原样保留。

基于 Python、Streamlit 和 SQLite 的本地个人技术情报平台。仅通过 GitHub API 获取公开仓库元数据，不下载或执行候选仓库代码。

## 功能与边界

- 按网络安全、AI Agent、系统工程、论文复现关键词发现最近 90 天创建的仓库，持续刷新所有已追踪仓库。
- 每个仓库每次采集任务最多生成一条 Star/Fork/Open Issues 快照；一天可运行多次，不覆盖历史。
- 项目浏览、字面关键词筛选、增长榜、历史曲线、数据质量和任务错误记录。
- 所有项目默认展示中文简介，支持中文关键词搜索；保留 GitHub 原始简介，可在详情中展开核对。
- 终端显示阶段、进度、当前项目、累计新增/快照/错误；页面顶部每 3 秒轮询已提交的任务进度。
- 搜索覆盖范围受关键词、分页及 GitHub 限流影响，不代表 GitHub 全量仓库。GitHub 的 Open Issues 计数也包含打开的 PR。

## 运行环境

Python 3.10+，依赖见 `requirements.txt`。已有 `.venv` 时直接使用，不必重建或升级依赖。

首次部署到新目录时：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
# 仅当 .env 不存在时创建；已有配置不会覆盖。
if [ ! -e .env ]; then (umask 077; cp .env.example .env); fi
chmod 600 .env
# 用本机编辑器编辑 .env，填入 GITHUB_TOKEN。
```

GitHub Token 仅需公开仓库读取权限，不需要写权限或私有仓库权限。不要将 Token 放到命令行、截图、日志或提交中。

在项目目录运行：

```bash
.venv/bin/python collector.py
.venv/bin/streamlit run app.py --server.address 127.0.0.1
```

前端通常位于 `http://127.0.0.1:8501`。采集器是独立进程，打开或刷新页面不会启动采集。页面进度自动更新；项目列表和历史曲线在点击“刷新项目数据”后更新。

### 中文项目简介

正常采集结束前会自动补齐中文简介。已有项目也可单独更新，无需 GitHub Token，不新增 Star 快照：

```bash
.venv/bin/python collector.py --translate-only
```

中文内容独立存储于 `description_zh`，`description` 保留原文；按原文缓存，未变化时不重复翻译。原文变化时清除旧译文并重新生成。明确为中文的简介直接复用，没有简介时显示“该项目暂未提供简介，请查看 GitHub 仓库了解详情。”，不推测项目功能。

翻译使用 Google Translate 的公开接口，将公开项目简介发送给翻译服务，不使用或发送 GitHub Token，也不需要新增 API Key。该接口的可用性受网络与服务限流影响。请求设有超时及最多 3 次尝试；多语言简介单独请求，批量结果通过标记校验对应关系。失败会记录为翻译错误，页面显示中文待生成提示，下次采集或单独更新时重试，不将未翻译的外文当作中文简介。列表及详情展示中文，关键词同时匹配中文、原文、仓库名和标签。

配置文件固定为项目根目录 `.env`，前端和采集器使用同一加载逻辑。进程环境变量优先，`DB_PATH` 的相对路径以项目根目录为基准。默认数据库为 `data/intel.db`。支持的采集配置：

| 配置 | 默认值 | 约束 |
| --- | --- | --- |
| `GITHUB_TOKEN` | 无 | 采集器要求非空；前端不要求 Token |
| `PER_PAGE` | 50 | 1–100 |
| `MAX_PAGES` | 2 | 1–10，且不超过 GitHub 每次搜索 1000 条的限制 |
| `DB_PATH` | `data/intel.db` | 可使用绝对路径 |

## 增长计算与数据质量

所有时间按 UTC 存储和展示。设最新快照时间为 T：

1. 查找 `T − 7 天` 或更早的最近快照，作为基线 B。
2. 区间增量为 `Star(T) − Star(B)`，支持负数；不会把缺失观测当作零。
3. 只有实际间隔在 **7–8 天**（包含边界）内，且 T 距现在不超过 **48 小时**，才显示“近 7 天增长（估算）”并纳入增长统计。
4. 基线确实为零时，可以计算绝对增长，但百分比没有定义，显示为空。

每日快照无法还原精确到秒的滚动周增长，因此页面明确标注“估算”，并展示实际起止时间及跨度。没有基线时显示“历史不足”；基线距离目标超过 24 小时显示“基线过旧”；最新采集超过 48 小时显示“数据过期”；未来时间显示“时间异常”；没有快照显示“尚无快照”。数据过期和时间异常优先于基线状态。

不合格项目仍可浏览；如果存在两次观测，详情会展示实际区间增量，但不当作周增长。默认不开启增长阈值筛选，避免首次运行时所有项目消失。启用增长筛选后只接受有效周增长，可以输入负阈值。所有趋势图遵守当前筛选；平均增长保留负数，排除缺失值，不将未知值按零平均。

## 采集流程与进度

采集分三个阶段，各自有独立的进度分母：

1. **发现阶段**：按关键词和最大页数安排搜索任务；不足一页时跳过该关键词的后续页面，这些跳过页面也计入阶段已处理数。仅更新仓库信息，不用搜索缓存计数生成快照。
2. **刷新阶段**：对所有已追踪仓库请求最新元数据，通过校验后，在一个短事务内更新仓库、写入快照、增加成功计数。每仓库每任务最多一条快照。失败项目保留旧快照，并记错误。
3. **中文简介阶段**：对缺失或原文变化的简介去重、翻译并缓存，每批译文单独提交。分母为待处理的不同原文数量；重复简介复用译文。

计数口径：`新增仓库` 为此次真正插入的记录；`匹配仓库` 为此次搜索命中的去重本地仓库数；`新快照` 为成功提交的快照条数。总错误为搜索、刷新、翻译及系统错误之和，翻译错误按失败批次计数。搜索不完整和搜索失败都会计入错误，不能被“刷新完成”掩盖。

终端示例：

```text
[refresh] 312/1795 17% | 新增 8 | 快照 310 | 错误 2 | 仓库已处理 | owner/project
```

页面使用已提交进度，不需要等待整批结束。限流等待期间仍更新心跳和倒计时。超过两分钟无心跳时提示检查进程，不擅自判定失败。可在“采集记录”查看结构化错误；错误不保存原始响应体、Authorization、Token 或完整 HTTP 异常。

状态与退出码：

| 状态 | 含义 | 退出码 |
| --- | --- | --- |
| 成功 | 无错误完成 | 0 |
| 部分成功 | 有成功快照，同时有搜索、刷新或翻译错误；单独更新简介时有翻译错误 | 1 |
| 失败 | 致命错误，或有错误且未成功写入快照 | 1 |
| 已中断 | Ctrl+C / SIGTERM，保留已提交结果 | 130 |
| 未启动 | 配置不合法、缺少 Token 或已有采集任务 | 2 |

使用数据库旁的文件锁防止多个本机采集器并发运行，锁文件存在不代表仍持锁。不要删除锁文件来“解锁”。如果进程被 SIGKILL 或机器断电，下一次采集获得锁后会把先前未收尾任务标为中断；不会伪造其真实结束时间。旧版记录保留原始计数和未知状态，不推断其是否完全成功。

API 的超时、连接异常、429、限流 403 和部分 5xx 最多尝试 4 次；优先遵守 `Retry-After` 和速率重置时间，单次要求等待超过一小时会停止该请求并记录错误。401 立即结束任务。重定向仅允许 HTTPS 的 `api.github.com`，防止凭据被发送给其他站点。

## 仓库身份与分类

后续采集使用 GitHub 稳定仓库 ID 识别项目，仓库改名或转移时更新名称并保留本地 ID 和历史。旧记录在首次成功刷新时补全 GitHub ID。遇到旧新记录冲突或名称被另一 GitHub ID 复用时，记录错误并保留全部历史，需人工核对，不自动猜测合并。

分类遵循首次入库结果，后续搜索命中其他领域不覆盖原分类。未知分类使用 `Other`。多标签分类暂未实现。

## 数据库迁移、备份与恢复

本次修改前的代码、配置及数据库备份位于项目 `backups/` 中。该目录含敏感配置备份，应保持私有；已加入忽略规则。

首次打开旧库时会在数据库旁 `backups/pre-v<目标版本>-*.sqlite3` 中使用 SQLite Backup API 创建一致性备份（包含已提交的 WAL 内容），检查完整性后才进行事务性、增量式迁移。当前版本为 2，新增中文简介、对应原文及翻译错误计数。重复初始化不会重复迁移。保留旧仓库、全部历史快照和任务记录；不清空数据库。发现旧数据约束异常会回滚迁移并要求人工核对。

新连接启用外键；快照写入校验计数类型、非负值和时间有效性。旧快照保留 `run_id=NULL`，不虚构其任务归属；新快照通过 `(run_id, repo_id)` 唯一约束保证幂等。

恢复时先停止前端和采集器，保留当前数据库及关联的 WAL/SHM 文件，再使用确认过的完整备份恢复到指定路径。不要在数据库运行时直接复制或替换单个 `.db` 文件。若回滚代码，应同时使用匹配版本的数据库备份；保留新库以免丢失回滚前新增的数据。

## 每天自动采集

先确认手动采集正常，再使用绝对路径配置 cron（替换为实际项目路径）：

```cron
15 2 * * * cd /path/to/project && /path/to/project/.venv/bin/python -u collector.py >> /path/to/project/collector.log 2>&1
```

cron 时间按主机本地时区解释，数据仍为 UTC。日志包含进度，建议按本机策略轮转。前端保持绑定 `127.0.0.1`；如需多人或公网访问，另行配置认证和访问控制。
