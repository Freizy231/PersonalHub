# M9 提案：Natural-language Software Creation（含带界面的 Personal App）

> 状态：**待用户批准**，未实施。
> 依据：`AGENT.md` §4.15 System Builder、M9 交付清单、§13.2「修改正式内核 / 扩大执行权限需先说明」、
> §13.3 提案格式。
> 日期：2026-11-24

---

## 1. 背景与当前问题

用户愿景（`AGENT.md` §1.3）：「每个人都可以拥有自己的 AI 环境……用户以自然语言
描述意图，系统将意图转化为需求、设计、软件能力和可运行应用」。

M8 已完成扩展能力基础设施，但只覆盖了**一半**：

| 用户想要的 | 现在能做吗 |
|---|---|
| “给 AI 增加一个查天气的工具” | ✅ 插件（声明式/进程） |
| “做一个记账页面，能记、能看、能统计” | ❌ **做不了** |

原因：插件只能注册**工具**（模型可调用的函数），无法提供**界面**。
`AGENT.md` §4.15 把二者列为不同类型：

> Plugin：包含代码、工具、UI、配置或依赖的安装包
> Personal App：组合多个能力形成用户应用

当前实现的是 Plugin 的工具部分。**Personal App 完全没有实现。**

另一个差距：现在写插件要求用户自己写 `plugin.json` 与 `run.py`。
而愿景是**用户描述、AI 来写**。M9 补的正是这一段。

---

## 2. 目标与非目标

### 目标

- 用户用自然语言描述需求 → 系统生成一个**可运行的应用**（含界面）；
- 生成物在**隔离的开发空间**（Staging）中生成与测试，不碰生产内核；
- 用户能**预览**、能**测试**、能**批准安装**、安装失败能**回滚**；
- 生成的代码**永不自动执行**、**永不被信任**；
- v1 只做**单文件只读展示型应用**（见 §5.3 的分级）。

### 非目标（v1 不做）

- AI 修改生产内核（§4.15 明令禁止）
- 应用之间互相调用
- 应用的持久化数据（v1 应用**不能存数据**，见 §5.4）
- 多文件工程、构建步骤（Node/打包器）
- 社区分享与签名（M10）
- 自动更新、版本迁移

---

## 3. 关键决策：生成的界面如何安全呈现

这是本提案最重要的部分。生成的应用是**第三方代码**，要在浏览器里运行。
如果直接把它塞进主界面（同源、同一个 React 树），它就能：

- 读 `localStorage` / 调用 `/api/*`（带着你的身份）；
- 篡改主界面的 DOM；
- 读取同源的其它页面。

**结论：生成的界面必须运行在独立的、无权限的沙箱里。**

### 方案 A：iframe + `sandbox` 属性 + 独立 origin（推荐）

```
<iframe
  src="/apps/{app_id}/index.html"
  sandbox="allow-scripts"      ← 关键：不给 allow-same-origin
  referrerpolicy="no-referrer"
/>
```

`allow-scripts` 但不给 `allow-same-origin` 时，iframe 被视为**不透明来源**
（opaque origin）。**以下已在 Edge 无头浏览器中实测验证**
（不是理论推断）：

| 应用内的尝试 | 实测结果 |
|---|---|
| `parent.document` | `SecurityError` |
| `localStorage.getItem()` | `SecurityError` |
| `document.cookie` | `SecurityError` |
| `fetch('http://example.com')` | `TypeError`（被 CSP 阻断）|
| 插入远程 `<img>` | 加载失败，网络面板无请求记录 |

再配合后端响应头，拦截剩余的越权面：

| 响应头 | 值 | 作用 |
|---|---|---|
| `Content-Security-Policy` | `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data:` | **禁止一切网络请求**（含 `fetch`/外链脚本/图片） |
| `X-Frame-Options` | 不设置（由 sandbox 控制） | — |
| `Cross-Origin-Resource-Policy` | `same-origin` | 阻止其它站点嵌入 |
| `Cache-Control` | `no-store` | 应用更新后不会读到旧版本 |

**优点**：零新依赖、浏览器原生保证、与现有前端架构兼容。
两层防护是**独立**的：CSP 挡网络，`sandbox` 挡同源访问；任一失效另一层仍在。
**缺点**：不透明来源下无法用 Cookie 鉴权，因此 v1 应用**不能调用后端 API**
（见 §5.4，这恰好与「v1 不做数据持久化」一致）。

### 方案 B：独立进程 + 独立端口提供应用

每个应用一个静态服务。隔离更强（真正的 origin 隔离），但需要进程管理、
端口分配、生命周期——对 v1 属于过度工程。**否决**（记录为 M9 之后的演进方向）。

### 方案 C：直接渲染生成的 React 组件到主界面

**否决**。同源、同 React 树，等于把第三方代码请进内核。这是最危险的做法。

### 推荐：方案 A

并追加约束：**应用只能在 iframe 里展示，不能出现在主文档中**。
预览与安装后运行**使用完全相同的机制**——预览不是"先放松再收紧"。

> 实测补充：`img-src data:` 允许内联图片，但远程图片会被阻断——
> 这在实测中确认（图片显示为破图，网络面板无 `example.com` 请求）。

## 4. 信任模型

| 风险 | 处理 |
|---|---|
| 应用偷看主界面 | 不透明来源 iframe，父 DOM 不可访问 |
| 应用盗用身份 | 无同源权限，Cookie/localStorage 不可用 |
| 应用外联 | CSP `default-src 'none'`，网络全禁 |
| 应用耗尽 CPU | `iframe` 无法限 CPU；改为**生成期限制**（见下）+ 应用复杂度限制 |
| 应用弹窗/跳转 | sandbox 不给 `allow-top-navigation`、`allow-popups` |
| 生成的代码含恶意内容 | 生成物**只读展示**，永不进入仓库、永不作为后端代码执行 |
| AI 生成时执行代码 | **生成与测试阶段都不执行生成的代码**（v1），只做静态检查 |
| 安装失败 | 版本目录 + 原子切换，失败保留上一版本 |

**关于"生成期不执行代码"**：v1 的应用是纯前端只读展示，
验证方式是**静态检查 + 浏览器沙箱中渲染截图**，而不是在后端跑它。
这让"生成"这一步本身没有任何执行风险。

## 5. 具体设计

### 5.1 组件划分

```
app/builder/
  requirement.py    需求解析：自然语言 -> 结构化需求（调用模型，输出严格 Schema）
  capability_search.py  检索已有能力（M8 的 CapabilityRegistry），优先复用
  generator.py      生成应用（调用模型，产出单文件 HTML）
  validate.py       静态检查：HTML 结构、CSP 兼容性、禁用 API、大小上限
  staging.py        Staging Workspace：临时目录、版本、原子安装、回滚
  registry.py       已安装应用注册表（与插件分层）
app/api/apps.py     预览/安装/卸载/列表、静态文件服务（带安全响应头）
```

### 5.2 数据流

```
用户描述意图
  → Requirement Engine：解析为 {name, purpose, ui_elements, data_displayed}
  → Capability Search：查询是否已有能力可直接复用（先复用，其次组合，最后才生成）
  → Generator：模型产出**单文件 HTML**（内联 CSS/JS）
  → Validate：静态检查（见 5.3）
  → Staging：写入 staging/<app>/<version>/
  → 用户在沙箱 iframe 中预览（同一个加载机制）
  → 用户批准 → 原子移动到 apps/<app>/current/，记录版本
  → 卸载 = 移除注册 + 目录重命名保留（与插件一致的策略）
```

### 5.3 应用复杂度分级（v1 只做第 1 级）

| 级别 | 形态 | v1 |
|---|---|---|
| 1 | 单文件 HTML + 内联 CSS/JS，**只读展示**（计算器、清单模板、图表） | ✅ |
| 2 | 同上但可写 localStorage 存自己的数据 | ⏭ M9 之后 |
| 3 | 多文件工程 + 构建步骤 | ⏭ 远期 |
| 4 | 调用后端 API / 调用插件工具 | ⏭ 远期（需鉴权设计） |

**为什么 v1 只做第 1 级**：第 2 级起就要面对"应用数据存在哪、怎么备份、
卸载时删不删"——那是独立的设计问题（与 D-013 的任务/作业区分同理）。
先把"生成 → 预览 → 安装 → 回滚"这条链路做对。

### 5.4 静态检查清单（`validate.py`）

生成物必须全部通过，否则不进入 staging：

| 检查 | 原因 |
|---|---|
| 单文件，≤ 200 KB | 控制复杂度与体积 |
| 无 `<script src=...>` / `<link href=...>` | 违反 `default-src 'none'` |
| 无 `fetch(` / `XMLHttpRequest` / `WebSocket` / `EventSource` | 应用不得联网 |
| 无 `import(` 动态导入 | 同上 |
| 无 `<iframe>` / `<object>` / `<embed>` | 防止嵌套绕过 |
| 无 `document.cookie` / `localStorage`（v1） | v1 不存数据 |
| 无 `top` / `parent` 访问 | 防止穿透沙箱 |
| HTML 可解析、标签闭合 | 基本正确性 |

> 这些检查是**纵深防御的一层**，不是唯一防线。真正的保证来自
> iframe 的 `sandbox` 与 CSP——静态检查可能被绕过，浏览器不会。

### 5.5 生命周期与版本

```
apps/<id>/
  current -> versions/1.0.1    （符号链接或指针文件）
  versions/1.0.0/index.html
  versions/1.0.1/index.html
```

- 安装 = 写入新版本目录 + 原子切换指针（失败则指针不变，旧版本继续可用）；
- 回滚 = 指针切回上一版本；
- 卸载 = 取消注册 + 目录重命名保留（与插件一致，用户决定过这个策略）。

### 5.6 生成能力的边界

- 调用模型生成代码，**模型输出视为不可信**（§8.4）：必须先过静态检查才能落盘；
- 生成失败或检查不通过 → 明确告知原因，不产生任何文件；
- **不自动安装**：必须用户点击批准；
- 每次生成记录：需求、生成时间、模型、检查结果、版本号。

## 7. 需要你决定的问题

1. **v1 是否只做"只读展示型应用"（第 1 级）**，暂不做数据持久化？
   我建议是——它能让整条链路先跑通，且不引入"应用数据存哪、怎么备份"的问题。
2. **应用能不能带数据**（localStorage）？
   - 能：更实用，但数据在浏览器里、清缓存即丢，且需要重新审视沙箱权限；
   - 不能：更简单，先保证链路正确。
3. **是否接受"生成期不执行生成的代码"**（只用静态检查 + 人工预览验证）？
   我建议接受：这让生成步骤本身零风险，代价是错误要到预览时才发现。

## 9. 测试与验收

**单元**
- 需求解析：模型输出非法/缺字段 → 拒绝，不产生半成品
- 静态检查：逐条覆盖 §5.4 的每个禁项（联网、外链、iframe、cookie 等）
- 版本：安装失败不破坏旧版本；回滚切回上一版本；卸载保留目录

**集成（真实浏览器）**
- 生成的应用在 iframe 中渲染成功；
- 在应用内尝试 `fetch('http://example.com')` → 被 CSP 阻断（读取控制台错误或网络记录）
- 在应用内尝试 `parent.document` → 抛错（跨源）
- 在应用内尝试 `localStorage` → 抛错（不透明来源）

**验收标准**（对应 M9 原文）

状态记录于 2026-11-24，各项的证据见 `docs/DECISIONS.md` D-020 ~ D-024。

- [x] 用户仅通过自然语言描述，系统生成可预览的应用
      （`POST /apps/generate` + 「应用」页预览；实机验证以番茄钟为例）
- [x] 生成物经过自动检查，不通过则不落盘
      （`generate_app` 检查不过即抛错；测试断言 `staging/` 里没有子目录）
- [x] 用户批准后才安装
      （生成只写 staging；安装是单独的 `POST /apps/staging/{id}/install`）
- [x] 安装失败可回滚到上一版本
      （先写版本、再切指针；`POST /apps/{id}/rollback`；接口测试覆盖）
- [x] 应用无法访问主界面、无法联网、无法读取身份
      （无头浏览器实测：父页面 / localStorage / cookie 均 `SecurityError`，
      `window["fe"+"tch"]` 被 CSP 阻断，网络记录为零）
