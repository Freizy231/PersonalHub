## 2. 不可破坏的资产

1. 不删除/清空/覆盖现有数据库及历史快照，不运行`DROP`/`TRUNCATE`或批量删除作为开发捷径。
2. 不覆盖根目录.env，不打印/提交GitHub Token；不能把秘密复制到日志、文档、截图或命令参数。
3. 不随意升级依赖；优先现有venv，新增栈分阶段独立锁定。升级必须说明必要性、兼容影响和验证。
4. 本轮不重写`app.py`、`collector.py`、`db.py`；未来必要改动只在明确授权的迁移任务中小步实施和回归，不全量推翻。
5. 旧`data/backups/`、`backups/`、`.env`备份、原始资料与锁文件不可随意删除；锁文件存在不等于持锁，不删inode来解锁。
6. 不执行外部下载的未知代码，不自动克隆并运行情报仓库或恶意样本。
7. 不上传个人文件，不擅自引入云AI或第三方自动诊断；AI关闭不影响业务。
8. 不提前引入社区、多用户ACL、微服务或向量集群。
9. 不修改用户未授权的其他工程；发现外部财务系统先评估入口/适配，不重造。
10. 路径缺失/版本不兼容要失败并提示，不能静默创建空库导致用户误以为历史丢失。

## 3. 读写数据库规则

审查用SQLite URI `mode=ro`和`PRAGMA query_only=ON`，先确认文件存在；不要为获取schema运行`app.py`/`init_db()`/collector。使用`PRAGMA table_info/index_list/user_version`和聚合计数，默认不读出私密正文/配置。SQLite在线一致性备份用Backup API，不在线直接复制单个.db；需要跨DB/文件一致性则协调停写。

两库过渡是基线：旧intel.db由旧迁移器/旧Collector管理，新hub.db由Alembic管理。严禁两个迁移器操作同一批表；禁止在API启动时执行生产自动升级或`create_all()`掩盖遗漏。版本检查只读，升级独立维护命令。每次升级：副本演练→行级/完整性检查→停写备份→显式迁移→验收→回退记录。不进行破坏性downgrade；恢复匹配程序+备份，保留升级后新增数据用于核对。

FK正常业务每连接启用；唯一维护例外为ADR-0003经备份/演练的父表copy，BEGIN前关闭、提交前FK与原表全行核验，不可推广到API。短事务、有限锁等待；HTTP/PDF/模型耗时不进写事务。SQL参数化，动态表列只能来自程序白名单。Resource创建/扩展/Activity同事务；文件写遵守操作日志和hash校验，不能声称DB事务能原子覆盖文件系统。

## 4. 模型与模块规则

- Resource仅公共身份/隐私/生命周期，具体字段进业务表；不得无schema地把一切塞metadata_json。
- 新资源用UUID；旧Integer ID保留映射；日期与时间按DATA_MODEL区分；历史NULL不能“补0”伪造事实。
- Task/Note/Document/Tag/Collection只实现一套共享服务。Learning和Projects调用这些服务；普通日记使用Note存储，Life负责视图。私密日记/树洞由同一Note领域的独立加密存储适配器管理，遵守DATA_MODEL的vault例外；不能将真实标题/正文/标签/修订落到普通SQLite或Markdown。
- 强业务关系用FK，松散关系用注册typed relations，禁止两套可写关联互相漂移。
- 原始来源数据与人工修正分开；旧原始JSON缺失则注明，不推测重建。GitHub仓库不是个人Project。
- 常规软删除，物理清理独立预览确认；不得CASCADE删除独立知识资产/项目源码/音乐原件。
- API DTO显式字段，搜索/活动/标签计数/关联/AI均服务端隐私过滤；不能只靠前端隐藏。

## 5. UI与实现质量

遵守UI规范：左导航、克制视觉、明暗主题、清晰空/错误/保存/冲突状态；优先列表而非所有内容卡片化。首页组件是投影，不复制业务数据。普通动作≤3次交互是目标，高风险确认不为省点击省略。

表单校验覆盖未知/缺失/零值；列表分页；渐进加载；长任务有进度、取消和逐项失败结果；断网不清空本地历史。保存失败保护草稿；并发版本冲突不最后写入获胜。不要在前台GET、页面刷新或后台AI响应中启动隐式采集/执行。

外部软件先注册白名单、参数数组、路径校验、预览和二次确认；不拼shell，不允许模型变成通用命令执行器。调用专业工具是管理入口，不制造内嵌完整播放器、IDE或恶意代码执行环境。

## 6. 测试与验收

按风险选择有意义测试；当前按用户功能优先指令推进Phase3的独立闭环。修改数据迁移/算法/安全边界必须有测试，简单可逆样式更改不为覆盖率写镜像测试。

现有回归基线：

```bash
.venv/bin/python -B -m unittest discover -s tests -v
```

原有51项回归保留，当前根目录套件另含数据保护与源码打包测试；新后端有独立ASGI安全/迁移基线测试。命令、结果和限制见OPERATIONS与版本说明。使用临时DB/伪Token/模拟API，不改为生产写入测试。前端构建不能代替真实浏览器E2E，沙箱绑定限制也不能视为通过。

必测风险：旧数据全字段不变、WAL备份、迁移失败回滚、未知新版本拒写、文件保存中断/冲突、私密搜索/摘要/标签泄漏、ID幂等、时区/全天边界、PDF坏文件/扫描/密码、启动参数注入、模型离线/提示注入。性能按PRD数据规模与p95口径，不用单次观察代替承诺。

模拟网络通过与真实平台端到端分开报告；无真实凭据/网络就写未验证，不能“应该能用”当验收。完成必需检查后不反复无理由扩大测试范围，继续交付。

## 7. 依赖、工具与数据处理

不重新安装已有环境；确认必要性后才加入FastAPI/Vue等新依赖。Python/Node版本、锁文件、启动方式写入说明；PyMuPDF等许可证在引入前确认。不要因规划阶段存在某技术选项就先全部安装。

私密文件只本机处理；调用任何翻译/摘要/网页接口要区分公开资料和用户内容。现有Google翻译仅公开仓库简介，不可直接套用到PDF/日记。当前模型使用用户配置API，不部署本地模型，不自动云兜底；外发需显式预览确认。测试样例不包含真实Token或个人心事。

## 8. 交付、变更记录与停止

每次交付说明：完成任务ID、实际改变、为何需要、验证命令及结果、数据库/文件影响、回退方式、仍未解决风险/决策。更新PRD/模型/API/UI/ROADMAP受影响部分和HANDOFF的当前版本/下一任务，不堆积互相矛盾的历史描述。

架构/数据决策需记录ADR：背景、选择、理由、影响、替代条件；例行实现不为每个函数写ADR。Git可用时只提交任务相关文件，检查秘密和数据未加入；当前Git不可用不得声称已提交，不删除受限.git目录。

任务完成更新记录，已授权的后续阶段须在前置门禁通过后继续；不外发周报、发布社区或上线公网。遇到确实需要用户选择的未决项，先完成不依赖该决策的具体可评审结果，明确问题来源与影响，不反复请求已授权动作的批准。
