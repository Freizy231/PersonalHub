# ADR-0011：本地饮食计划与实际库存分离

2026-11-12｜v0.11.0｜P3-03

## 决策

食谱是普通 personal Resource（共享标签、集合、关系和搜索）；食材是饮食模块的规范名称目录，不成为通用资源。食谱保存基准份数、步骤、常用标记及结构化食材行。菜单为本地日期+早/中/晚餐的多道食谱记录，每条有份数、备注和独立版本。仅人工输入，不联网抓取，不引入AI/医学营养。

数量从十进制字符串解析，至多三位小数，存INTEGER千分单位。固定单位g/kg/ml/l/piece/portion；建议统一kg→g、l→ml，质量、体积、个、份绝不互换。份数比值用整数运算，每个食谱行向上取整至千分单位，避免浮点和短缺。无密度推算。

周以周一DATE表示（亚洲上海本地日期由首页请求传入，不转换UTC）。每周购物表GET无记录时返回version0，不写盘。建议根据当前可见菜单、食谱、库存以及已确认的未移除购物项重新计算：缺口=max(需求-库存-本周已确认量,0)。已买项目仍计入已确认量，勾选不入库。显示总需求/库存/已确认/建议追加，需求减少也不删清单。

预览是只读结果及确定性摘要；用户选择建议再明确确认，服务端同写事务重新计算摘要、检查周清单CAS后追加快照行。任何相关事实变化使预览过期。已确认行有独立ID，可编辑数量、单位、备注、已买状态，也能移除/恢复；任何菜单/食谱变化都不更新它。手工行可自选食材，不混合不可换算单位。库存按食材+规范单位的单一余额，明确手工盘点覆盖余额（含0），CAS和幂等；购物勾选/菜单保存不扣库存、不自动入库。不做库存流水/保质期/营养系统。

私密Resource不返回身份、计数、食材衍生需求或幂等重放；回收食谱暂隐藏其菜单，可恢复。购物确认是当时人工保存的普通事实，与原食谱独立。真实私密内容仍只进加密vault。

## 迁移与替代

0010_diet扩Resource CHECK以允许recipe，使用既有维护事务父表重建流程；保持原行和原索引，遇未知触发器拒绝。新增七表：diet_ingredients/recipes/recipe_ingredients/meal_plans/shopping_lists/shopping_items/inventory_balances。完整v3快照含所有表，普通ZIP含所有饮食普通事实；不含外部文件/隐私。不更改0000～0009，不启动自动迁移。

后续需要采购入库/消耗流水时增加显式事务和新迁移，不将菜单状态当库存扣减事件。开放任意单位会降低可靠聚合，暂采用固定枚举；高级库存与食谱图片暂后置。
