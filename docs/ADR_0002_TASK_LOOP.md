# ADR-0002：第二版普通任务闭环与显式升级

日期：2026-11-11｜状态：采用｜版本：v0.2.0，P1-01a

## 背景与范围

用户明确要求继续第二版，并确认上一版本机浏览器“已正常打开”。这补充基本启动证据，但不代表P0-A5全部外观/断网/攻击场景或本版任务E2E已完成。遵循此次继续开发指令交付可审查、可本机试用的任务小版本；保留完整门禁待验收，不能借此宣称Phase1完成。执行环境仍不能连接用户的本机服务，因此本版报告ASGI/组件与构建验证，不虚构浏览器结果。

## 决定

1. 只实现Resource/Task/Activity/operation_requests，不提前建日历/Note/学习/Project。Resource kind CHECK当前仅task，未来资源类型必须通过独立增量迁移扩展，不假定目标模型已全落地。
2. 使用SQLAlchemy Core显式表与短事务，复用身份/活动。当前无需复杂Repository/插件框架，模块life/tasks持有schema/service/router。缺库/未知版本拒写，API启动不迁移。
3. upgrade维护命令对新hub.db做Backup API备份→隔离恢复副本→副本Alembic升级与原表指纹对照→BEGIN IMMEDIATE复核原库未变化→事务化DDL与revision提交。若原库在备份后变化则拒绝本次升级，保留备份并要求重新建立基线；不做破坏性downgrade。DDL事务内失败回滚；提交后若报告落盘失败，须运行check与只读检查确认当前revision，不能假定已回退或直接恢复覆盖。
4. API生命周期持共享flock，升级/备份维护持排他锁，锁文件在私有config目录，不删除inode解锁。现有v0.1无该锁，但只有只读入口；升级说明仍要求停止旧新Hub进程。旧Collector/Streamlit不受新锁管辖，新工具不访问intel.db。
5. 写API在线程中执行，以免SQLite锁等待阻塞事件循环。当前沙箱跨线程唤醒不可靠，测试使用有周期唤醒的SelectorEventLoop，仍跑真实线程/SQLite/事务，不替换业务。该兼容层只存在测试代码，生产不用轮询。
6. 任务是普通明文个人资料；privileged/private API不开放。说明按文本显示，未来Markdown需单独净化。日期与精确时间分开，任务自身时区决定日期截止边界。首页今日只代表计划日，不擅自将所有到期项挤入日计划。
7. 创建用持久幂等键，编辑用expected_version；失败保留草稿，冲突不自动覆盖。删除可恢复，无永久删除。JSON导出供交换，SQLite备份供原样恢复，当前无JSON导入。
8. 前端交互测试使用真实编译Vue组件、内存renderer、替代Naive UI展示部件和模拟API，验证失败草稿/重试/冲突；不能替代浏览器CSS/键盘/原生日期控件验收。不增加测试依赖，直接Node执行node:test测试API，绕过受限沙箱子进程IPC报告问题。

## 后续

本版真实本机任务CRUD/重启/两主题/断网验收完成后，继续P1-02 Event/一次性站内提醒。私密库仍按独立加密方案在后续专门实现，当前禁止录入。首次引入Note文件前必须把目前的数据库备份升级成数据库+文件一致性全量恢复；不因当前SQLite-only能恢复就宣称未来文件也受保护。
