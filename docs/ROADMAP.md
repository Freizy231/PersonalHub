## 1. 执行方式与估算

采用“最小可用闭环→真实使用→修复稳定性→扩模块”的顺序。Phase 0 必须先于个人资料录入；后续阶段不代表一次大版本，按下列任务拆为可独立验收的小批次。P0是安全与数据保护，P1～P4是交付顺序，Phase5是未来研究。

估算以一名熟悉Python/Vue的开发者、现有Ubuntu环境为前提，单位为有效人日，包含设计细化/实现/测试/文档，不承诺日历工期；不含等待用户决策、硬件/联网排障和大规模资料整理。每阶段范围确认后重新估算，建议另留20%～30%不确定性缓冲，不能以时间到期跳过门禁。

公共完成定义：对应功能/错误/离线/隐私验收通过；迁移在副本演练；旧数据保护核对；依赖有锁定记录；已知限制写回文档/HANDOFF；有匹配版本回退说明。不能用“页面能打开”代替完成。

## 2. Phase 0：审查落实、数据保护与架构基础

**目标**：把本次文档审查转化为可重复、可验证的安全开发环境；不改变旧业务行为。

**范围**：只读清单、脱敏基线、Backup API一致性备份和恢复演练；明确D-01数据目录、D-03备份介质/策略；核实真实Python/系统硬件/磁盘；解决版本管理工作区限制；最小新后端/前端骨架与只读健康页（在备份门禁后）。

**不做**：不启动采集、不迁移生产intel.db、不录入敏感日记、不实现任务/PDF/AI，不一次建立全部模块目录，不重写三个旧入口。

**任务顺序**：

1. **P0-01（已完成）**：新增只读审计+备份/恢复验证维护工具，参数显式指定旧库；缺失路径立即失败，绝不创建空库。输出schema版本、表计数、完整性、外键、脱敏manifest；使用Backup API写入新的独立备份文件，拒绝覆盖。恢复到临时隔离目录，核对全部原字段和校验值。工具不导入会初始化数据库的UI，不读出Token。
2. **P0-02**：确认数据/备份位置与权限；明确旧.env、备份中.env的保护；记录cron/systemd是否真实存在（本次未查）；建立恢复运行手册。无异盘介质时明确仅防误改、不防磁盘损坏。
3. **P0-03**：核实 `.git` 工作区不可用原因，使用用户指定可写版本管理方式，不删占位目录。记录当前依赖和解释器，不升级旧venv。评估新栈兼容并生成独立锁定清单。
4. **P0-04**：按架构建立最小frontend/backend入口、同源本机访问、会话/Origin防护、配置校验、只读健康接口，明确新hub.db与旧库边界。只在隔离环境演练新库空基线；生产路径不存在不能静默建库。
5. **P0-05**：验证启动/停止/数据目录权限/离线可用；记录ADR（选型、两库过渡、迁移职责）与任务拆分。

**数据库变化**：本阶段生产旧库0变化；新库在独立runtime/personal-hub路径显式初始化Alembic空基线，备份记录可先JSON，不强行建业务表。

**页面变化**：设计中的导航外壳/健康页原型，可链接旧Streamlit；不宣称已实现八模块。

**验收**：

- P0-A1：任意不存在DB路径拒绝运行，不产生新DB；权限错误不降级成空库。
- P0-A2：复制备份到隔离目录后 `integrity_check=ok`、FK无异常；四个旧表全字段逐行一致（基线1796/3641/3/0是本次观察，正式运行以工具实时一致性清单为准）。
- P0-A3：备份包含已提交WAL内容；中途失败不覆盖旧备份；写入者活跃时使用Backup API，整体灾备需要协调停写。测试模拟WAL与异常。
- P0-A4：`.env`及旧代码/依赖哈希不变，输出/日志没有Token；恢复不写回生产路径；全部51个既有测试继续通过。
- P0-A5：本地健康页绑定127.0.0.1且外部Origin写请求被拒；恢复流程有操作记录和失败回退说明。

**风险**：受限Git环境、备份同盘、未确认后台采集、依赖兼容、路径指错。**难度**：中；约4～7人日。P0-01可先独立完成，约1～2人日。

## 3. Phase 1：日常入口与最小生活闭环

**目标**：每天可以打开首页安排一天、记录想法与日记；无AI/无网络也可用。

**范围**：Dashboard基础组件/布局；Task、Event、站内提醒；快速记录收件箱、Markdown日记/树洞；标签/集合/关联基础、普通全文搜索；基础设置、完整导出、备份/恢复入口。旧情报入口保留；应用启动第一版只做内部页/安全URL快捷入口，原生应用执行等Phase3。

**不做**：复杂重复日程、CalDAV、移动端完整适配、学习系统、PDF、饮食/音乐/财务、AI、社区。D-02已选独立加密库；加密与解锁验收通过前不得保存真实敏感内容，可先完成普通任务和非敏感笔记。

**技术任务**：P1-01新hub.db显式Alembic初始化及Core资源服务；P1-02Task/Event/Reminder API及日历语义；P1-03普通Note本地文件/修订/冲突/操作日志，以及独立加密库/解锁/自动锁定专门设计与实现；P1-04Vue外壳+首页组件+任务/日记页面；P1-05搜索过滤/隐私分区/布局设置；P1-06任务持久化、离线、备份恢复与导出全链路。先做一个任务CRUD纵向链路再推广模式，禁止先搭全功能框架。

**数据库变化**：Resource/Tag/Collection、关联、Task/Event/Note、Activity、Reminder、布局/设置、后台任务/文件操作/幂等记录/搜索投影。没有Project/KnowledgeNode表前不提前创建引用它们的FK列。legacy映射只在新情报投影实际需要时加入。

**页面变化**：UI规范中的外壳、首页5组件、生活任务/日历/日记/私密范围、全局搜索、Settings基础/目录/备份/导出；未实现模块显示阶段说明。

**验收**：

- P1-A1（DASH/LIFE-T）：首页创建任务→安排今日→完成→重启仍保留；逾期/定时截止/全天日程/跨时区日期正确；勾选失败明确回滚。
- P1-A2（LIFE-N/LIB-06）：快速记录入收件箱，Markdown保存在代码目录外；模拟保存中断可恢复；外部编辑冲突409/另存，不覆盖原文。
- P1-A3（隐私）：private正文、标题、计数、标签命中、关联摘要不出现普通首页/搜索/活动；按D-02验收约定的锁定/解锁与物理保护边界。
- P1-A4（提醒）：重复启动不重复投递；机器离线后重启按24h补偿规则；关机不承诺提醒。
- P1-A5（可用性）：明暗两主题、两个桌面尺寸、键盘入口/排序；布局显隐重排重启保留。
- P1-A6（数据）：断网+关闭Ollama完成全部核心操作；完整导出→新目录恢复→资源/Note/关联一致，旧intel.db和.env不变；API/文件保存异常不显示假成功。
- P1-A7（质量）：按PRD规模/测量方式记录首页、写入、搜索p95；性能不达标先修主要路径，不扩大范围。

**风险**：SQLite/文件非原子、隐私被摘要泄漏、时区、锁策略与用户预期差异。**难度**：高；约12～20人日。发布后建议真实使用一周并处理数据/交互问题，再开始Phase2。

## 4. Phase 2：资料库与学习成果闭环

**目标**：把资料、知识点、练习和验收连接起来，而不仅统计时长。

**范围**：PDF单/多导入、哈希去重、元数据/文本提取、FTS、状态/进度/书签、外部阅读器入口；书籍/网页元数据、Markdown知识笔记/双向链接；学习目标/路线/知识树/课程/学习记录/成果验收/阶段复盘。

**不做**：OCR、复杂内置阅读器、高亮批注编辑、自动拉取付费全文、网页完整归档、复杂图谱推理、RAG/AI计划、正式个人Project模块。项目先使用已有仓库URL/Note关联，不造临时Project表。

**技术任务**：P2-01上传staging/Blob/幂等与文件校验；P2-02PDF提取适配器隔离进程、资源预算、失败重试（v0.8采用已安装Poppler，见ADR-0008）；P2-03FTS中文/短词/私密范围验证；P2-04Library页面与阅读状态；P2-05Learning路径/节点/会话/验收；P2-06双向链接重建和导出恢复。核实PDF库许可证、默认大小/批量上限和D-04中的阅读器调用配置。本阶段提前实现仅限PDF阅读器的最小白名单启动配置/预览/二次确认，Phase3复用并扩展到其他工具；不提供任意命令。

**数据库变化**：Blob/Document/书签、Book/Bookmark/Course、LearningGoal/Path/Node及成员/Assessment/Evidence/Session/Review；Task通过learning_node_tasks多对多关联知识点（代替单值learning_node_id，见ADR-0008）；搜索投影支持提取文本；新增仅限PDF阅读器的external_app_profiles/launch_history。已有资源ID保持不变。

**页面变化**：资料库列表/导入任务/文献详情/笔记编辑；学习目标/路线树/知识点验收/复盘；首页可添加在读资料、学习计划、每周成果组件。

**验收**：

- P2-A1（LIB-01）：同批/跨批/并发上传相同PDF仅一个Blob+Document；重复可补标签，原用户文件不变；大小/类型/磁盘不足/中断逐文件报错，hash与恢复后原件一致。
- P2-A2（LIB-02）：正常、损坏、加密、扫描版、多语言PDF各有明确状态；坏PDF/超时提取不拖垮API；无需AI可搜文本，无文字不冒充已索引。
- P2-A3（LIB-03～07）：有效页码、书签、书籍无文件、网页仅元数据、稳定UUID链接、反向链接；用户目录迁移后链接不失效，外部阅读器进度不伪造。
- P2-A4（LEARN）：完成“PE导入表”场景：目标→知识点→材料→练习任务→成果/实验笔记→明确验收→复盘；记录10小时不能自动verified；路线分母明确且无环。
- P2-A5（安全/恢复）：以private PDF/Note验证搜索、片段、重复提示、关联和导出；升级副本逐行保护旧资源；完整备份恢复包括PDF/修订/关系，索引可重建；达到PRD性能目标或记录调整决策。

**风险**：不可信PDF、磁盘/提取资源、中文FTS、文件一致性、模型过重。**难度**：高；约18～28人日，可将Library与Learning拆为两个发布。

## 5. Phase 3：项目与生活工具入口

**目标**：把日常专业工具与已有记录统一连接，不复制专业软件能力。

**范围**：个人Project、任务/里程碑/文献/日志/实验/总结、目录与外部应用配置；饮食三餐/周菜单/食谱/库存/购物；财务调查与入口/只读适配或经决策的轻量账本；运动记录/计划/日历/统计。照片和其他资料仅目录入口。

**不做**：完整IDE/终端模拟器/播放器、自动执行恶意样本、音乐平台破解接口、医学营养建议、银行同步、重复财务系统、专业相册、设备自动同步、任意AI执行。

**技术任务**：P3-01项目与资源关联；P3-02扩展Phase2的服务端应用白名单/路径校验/预览确认/启动日志；P3-03饮食小闭环；P3-04本地音乐已取消，不实施；P3-05先调查D-05，写适配决策，再做入口或账本；P3-06运动与公共日历/任务融合。各子模块独立验收，不要求一口气发布。

**数据库变化**：Project/里程碑及project_tasks单项目归属（v0.9）；保留PDF阅读器专用配置，新增项目工具配置/预览/历史（v0.10）；后续扩展快捷方式app类型；饮食表、Exercise；音乐相关表已取消，不创建；财务仅在D-05决定新建时引入账户/交易/预算。库存与金额不能存成一堆无schema JSON。

**页面变化**：项目列表/详情和工具预览；生活饮食/财务/运动二级页；首页解锁最近项目、应用启动器、今日三餐。学习知识点可正式关联Project。

**验收**：

- P3-A1（PROJ）：Malware Analysis Lab关联本地目录/GitHub/PDF/实验Note/Task；归档项目不删资料/代码；进度分母可解释。
- P3-A2（安全）：恶意参数/越界目录/符号链接/不存在程序被拒；点击启动须预览并二次确认；没有任何AI/网页文本变成shell执行；程序失败不破坏业务数据。
- P3-A3（饮食）：一周三餐→食谱→按单位对照库存→确认购物清单；改菜单不覆盖已确认购物项，计划不扣实际库存。
- P3-A4（音乐）：已取消，不再设实现或验收门禁，不创建音乐目录扫描、歌单或播放器适配。

## 6. Phase 4：多源情报与可选API助手

**目标**：保留可信采集基础，扩充来源并对本地知识提供可检查的辅助。

**范围**：独立Collector/来源状态/原始载荷/快照/关键词订阅/去重/领域/收藏/周报；按架构完成GitHub历史兼容切换；可配置API、选定资源总结/问答/检索、人工可编辑学习和饮食建议；验证有益后引入本地RAG。

**不做**：不同平台热度加总、未经授权抓取、默认云模型、自动发布、自动改掌握状态、自动删除/命令Agent、先搭向量集群。Reddit等来源可受权限限制保持禁用，不伪造已接入。

**技术任务**：

1. P4-01 GitHub适配和副本迁移：保留稳定Resource ID、逐字段对照、保留旧NULL run/未知原始JSON/原始状态。
2. P4-02 依次RSS/Atom→HN/arXiv→HF，Reddit/Lobsters/Product Hunt需D-06权限评估后分别排期；每来源独立测试与限流预算。
3. P4-03 原始载荷/指标窗口/趋势质量、跨来源同目标关联、订阅命中、人工模板周报。
4. P4-04 可配置API最小只读适配：显式选资料、超时取消、引用/页码、错误降级、私密范围、写入草稿确认。
5. P4-05 以真实查询评估FTS是否不足；需要语义检索才决定D-07的chunk/embedding方案，记录模型/版本/hash/隐私删除链；再加入RAG。

**数据库变化**：Source/Item/原始载荷/快照/Metric/Run/Error/Subscription/迁移映射；AI Run/Citation；RAG索引按验证结果按需增加，不一次建所有表。

**页面变化**：新版情报列表/详情/订阅/采集状态/周报；AI助手/模型设置/资源范围/引用；首页情报组件完整接入。

**验收**：

- P4-A1（INT-07）：停写切换演练保留四个旧表全部字段/记录及映射；零基线/负增长/历史不足/过期/微秒排序算法回归；不虚构缺失raw或run归属；没有新旧双写。

- P4-A3（AI）：关闭API助手后所有核心功能正常；本地问答引用可回溯；private默认不检索、不缓存、不写进周报；本次授权范围之外请求被拒。
- P4-A4（AI安全）：提示注入不能读取任意文件/密钥或调用命令；模型修改建议只成草稿；保存要确认且校验版本，删除/覆盖需独立二次确认。
- P4-A5（RAG门禁）：准备至少20个人工标注问题（含中英文、无答案、旧版本、私密排除），比较FTS/混合检索；报告引用正确率、命中率、无答案误答、时延和资源开销。只有有明确收益再启用；删除/隐私变更立即不可检索，向量/缓存可重建。
- P4-A6（来源接入）：每个已交付Collector有合法可用入口、凭据隔离与覆盖限制说明；未获权限来源明确标记“未接入”。真实网络验证单独记录，模拟通过不能冒称真实端到端完成。

**风险**：第三方API变化、跨源热度误导、迁移丢历史、模型幻觉/提示注入、CPU/GPU/内存预算、索引隐私残留。**难度**：很高；基础约20～35人日，受限平台另估，RAG附加约6～12人日。

## 7. Phase 5：内容分享与社区研究（冻结实施）

**目标**：在用户确有需求时评估个人内容分享，保护长期本地资产；未来社区不是现阶段依赖。

**范围**：先做需求研究、分享内容选择/脱敏/导出预览原型和独立架构评估。可能先交付静态分享包，而非在线社区。多人讨论、共同学习、内容权限和公开身份必须形成新的PRD。

**不做**：未经新授权上线网站、上传个人资料、注册/租户/社交图谱/复杂ACL、默认公开。不能自动将personal等同public。

**技术任务**：威胁建模、发布内容副本和隐私检查、所有权/撤回/版权评估；若确需托管社区，再单独决定部署、身份和同步方案。当前单体可继续独立使用。

**数据库变化**：当前无变化；后续仅在新设计获授权后增加分享包/发布记录，不能提前在所有表加tenant_id。

**页面变化**：规划中的“分享预览”原型；默认无在线发布入口。

**验收**：Phase5研究报告能说明分享对象/边界/撤回/是否上传，测试导出包不含private正文、文件路径、Token、隐藏关联或EXIF等意外元数据；完整离线核心不受影响。正式实施另行验收。

**风险**：不可撤回公开、隐私/版权、运维与多人边界。**难度**：研究中，约3～5人日；社区工程不估算、不授权。
