## 1. M10 规范原文与风险分级

M10 的六项交付，风险差得很远：

| # | 交付项 | 风险 | 依赖外部服务 | 数据外发 | 建议批次 |
|---|---|---|---|---|---|
| 1 | 数据导出/导入和加密备份 | 中（碰用户数据） | 否 | 否 | **第一批** |
| 2 | Extension/App Package 导出 | 低 | 否 | 否 | **第一批** |
| 3 | 包签名、版本、依赖、许可证 | 低 | 否 | 否 | **第一批** |
| 4 | 用户主动分享和撤回 | 高 | 是（若上传） | **是** | 第二批（需单独确认） |
| 5 | Community Registry | 高 | **是** | **是** | 第二批（需单独确认） |
| 6 | 可选设备同步 | 高 | 是（服务器） | **是** | 第三批（需单独确认） |

**本提案只请求批准第一批。** 第二、三批涉及把用户数据发到外部、以及运行一个
别人能访问的服务，需要你先决定"要不要做、做成什么样"——我在 §6 列出需要你回答的问题。

## 2. 第一批的目标与非目标

### 目标

1. **一致性备份**：用 SQLite 的在线备份 API 生成一份一致的数据库快照，
   而不是复制正在写入的文件（§4.13 明确禁止后者）。
2. **可选加密**：备份可以用口令加密；不加密时明确标注"未加密"，
   绝不暗示它已加密（§4.13：未验证前不得宣称数据库已加密）。
3. **导出**：把核心数据导出成可读、可迁移的 JSON（会话、记忆、任务），
   外加应用包。**导出是用户的动作，不是系统的动作**。
4. **应用包（`.phapp`）**：一个应用 + 清单（版本、权限、许可证、兼容性）
   打包成 zip，可以在另一台机器上导入。
5. **导入**：能读回自己导出的东西。导入应用包要重新过静态检查——
   别人的包和本机的包一样不可信。

### 非目标

- 不做同步（哪怕"可选"）。同步需要设备身份、冲突解决、删除传播，
  是一个独立的设计问题，不能塞进"导出"里顺手做。
- 不做上传、分享、注册表。
- 不做增量导出（先全量，够用，也更容易验证）。

## 3. 关键设计

### 3.1 一致性备份用 SQLite 的在线备份 API

```
sqlite3.connect(db_path).backup(dest_conn)
```

而不是 `shutil.copy`。原因：WAL 模式下数据库文件 + `-wal` + `-shm` 三者
共同构成一致状态；只复制主文件会得到一个**可能缺最近提交**的库，
而用户不会知道。在线备份 API 由 SQLite 自己保证一致性。

**已验证**：本机 Python 3.12 的 `sqlite3.Connection.backup` 可用。

### 3.2 加密：用口令派生的密钥 + AES-GCM

- 依赖：`cryptography` 已在依赖树中（经 `mcp` 的 `pyjwt[crypto]` 间接引入），
  但**间接依赖不能直接用**——必须是显式依赖，否则上层库改依赖时会静默崩溃。
  因此需要把它提升为直接依赖（`cryptography>=50,<51`，Apache-2.0/BSD 双许可）。
- 密钥派生：`scrypt`（`cryptography` 内置）从用户口令派生。
- 加密格式：文件头写明版本、KDF 参数（salt、n、r、p）、随后是 AES-GCM 密文。
  参数写进文件是要紧的：将来调整参数时旧备份仍然能解开。
- **口令不保存**。丢了口令就打不开备份——这一点在界面上必须说清楚。

### 3.3 应用包格式

```
<name>-<version>.phapp      （zip）
  manifest.json             应用清单（id、名称、版本、权限、许可证、兼容性、依赖）
  index.html                应用内容
  LICENSE                   许可证正文（作者提供）
  README.md                 可选说明
```

导入时：

- 清单逐字段校验（与 M8 Manifest 同一套严格规则：未知字段拒绝）；
- `index.html` **重新过 `validate_app`**——包里的代码和模型生成的代码一样不可信；
- 包内路径白名单：拒绝 `../`、绝对路径、符号链接条目；
- **导入应用不等于安装**：先落在 staging，用户预览确认后才安装（与生成一致）。

### 3.4 分享包不能带个人数据

这是 M10 验收里最硬的一条："分享包不包含个人记忆、私密文件和秘密"。

做法是**结构上保证**，而不是靠检查：

- 应用包只从 `apps/<id>/versions/<v>/` 取内容，该目录里**只可能有** `index.html`；
- 导出时**不**读取数据库、`apps/<id>/meta.json`（里面有 `source_request`，
  那是用户的原话）、staging、日志；
- 有一个测试：导入一个包含 `meta.json` 的包，断言 `source_request` 不会被带过来。

### 3.5 数据导出的内容边界

导出 JSON 只包含用户**自己创造**的东西：

| 表 | 导出 | 理由 |
|---|---|---|
| conversations / messages | ✅ | 用户的对话 |
| memory_items（仅 APPROVED + REJECTED 的选择） | ✅ | 用户确认或拒绝过的判断 |
| memory_items（PROPOSED） | ⚠️ 默认不导出 | 那是模型的猜测，不是用户的事实 |
| tasks | ✅ | 用户的任务 |
| approvals / tool_invocations | ❌ | 执行痕迹，不是用户数据 |
| job_queue / task_runs | ❌ | 内部调度状态，迁移后无意义 |

**不导出**：API Key（本来就不在库里）、任何环境变量。

### 3.6 恢复不是"覆盖当前数据"

导入备份时：

- **先备份当前数据**（自动生成一份 `pre-restore-*.db`），再替换——§4.13 要求；
- 或者更好：只允许**恢复到新目录**，让用户确认无误后再切换。
  我倾向后者，但它需要用户改 `PH_DATA_DIR`，体验差一些。

**默认实现**：自动备份当前库 → 替换 → 失败可回滚。界面上明确写"已保留替换前的备份"。

## 4. 实施顺序（第一批）

1. `app/backup/` 模块：一致性快照 + 口令加密 + 参数入文件头；纯文件操作，可完全单测。
2. 备份 API：`POST /backups`、`GET /backups`、`POST /backups/{name}/restore`（需确认参数）。
3. 数据导出：`GET /export/data`（JSON，流式）。
4. 应用包：`GET /apps/{id}/package`、`POST /apps/import`。
5. 前端：「设置」页（备份/导出/导入入口）。
6. 文档 + 技术债。

## 5. 影响

| 维度 | 影响 |
|---|---|
| 数据 | 新增 `backups/` 下的加密文件与导出 JSON。**不删除、不覆盖**用户现有数据 |
| 依赖 | `cryptography` 提升为**直接依赖**（已在树中，Apache-2.0/BSD，无新供应链风险） |
| API | 6 个新端点，全部本地操作 |
| 安全 | 备份可加密；不加解密能力之外的任何外部通道 |
| 数据库迁移 | **无** |

## 6. 需要你决定（第二批/第三批是否开工）

1. **社区注册表要不要做？** 它意味着运行/连接一个外部服务，且用户的应用包
   会被上传。我建议：**先不做**，等导出、包格式、签名都稳定并经过真实使用，
   再决定要不要一个注册表——过早做会把尚在变化的格式固化。
2. **设备同步要不要做？** 这需要一台服务器（或用户自建），且要设计设备身份、
   冲突解决、删除传播、密钥管理。我建议：**推迟到 1.0 之前单独设计**。
   规范自己也写了"不直接同步活跃 SQLite 数据库文件"，这需要一个 CRDT 或
   变更日志层，是独立且不小的工程。
3. **签名算法**：我建议 **Ed25519**（`cryptography` 提供）。密钥存哪？
   我建议存成数据目录里一个权限 0600 的文件，并在界面上提供"导出公钥"。
   不用 Keychain 是因为它跨平台差异大，现阶段引入会挡住 Linux 之外的用户。
4. **备份口令最低长度**？我建议 **12 字符**，少于它直接拒绝并说明原因。

---

## 7. 回滚

第一批全部是新增模块与端点，回滚 = 删除 `app/backup/`、`app/packages/`、
前端设置页与对应测试。**不需要回滚用户数据**：备份和导出都是只读操作
（恢复除外，它自带"先备份当前库"）。

## 8. 测试与验收

**单元**

- 快照：在有一个未检查点的 WAL 事务时备份，断言备份里能看到该事务
  （这是"不能简单复制文件"的直接证据）；
- 加密：正确口令能解、错误口令抛明确错误、文件头被篡改能被识别；
- 包：路径逃逸、超大文件、清单未知字段、`index.html` 未通过静态检查，全部拒绝；
- 导出：PROPOSED 记忆不在导出内容里；不含任何 Key。

**集成**

- 备份 → 修改数据 → 恢复 → 数据回到备份时刻，且替换前的库被自动保留；
- 导出 → 在临时目录导入 → 会话/记忆/任务数量一致；
- 应用包导出 → 在另一数据目录导入 → 能预览、能安装。

**验收标准**（对应 M10 原文，仅第一批部分）

- [ ] 用户可以导出自己的应用包，并在另一安装环境中安装
- [ ] 分享包不包含个人记忆、私密文件和秘密（结构保证 + 测试）
- [ ] 备份一致性可验证；加密可选且如实标注
- [ ] 恢复前自动保留当前数据的备份
- [ ] 社区与同步：**未实现，且产品中没有任何默认开启的入口**
