# ADR-0001：本机基础版本与受限环境运行方案

日期：2026-11-11｜状态：采用｜对应任务：P0-01～P0-05

## 背景

用户已授权按路线顺序迭代，并选择私密日记采用“独立加密库与解锁密码”；数据目录与异盘位置无指定。现有数据必须保留。根目录.git不可用且不可写，旧cron读取被权限拒绝；执行环境禁止loopback绑定，pip/npm直连受限，但已有批准的curl可访问官方包源。

## 决定与影响

1. 新个人数据暂放独立`runtime/personal-hub`，备份/隔离恢复在`runtime/backups`和`runtime/restore-checks`，全部忽略版本管理；不移动旧`data/intel.db`或.env。正常环境可以迁往XDG目录，但必须走后续校验/切换流程。无异盘时仅声明同盘恢复能力，不自动清理备份。
2. 新栈使用独立`backend/.venv`，保留旧venv和四项依赖；Python/前端分别锁定。官方包源下载经PyPI SHA-256或npm integrity校验，本地安装，不执行未知安装脚本。FastAPI依赖中的OpenTelemetry API仅为本地库，没有引入exporter、服务地址或云遥测。
3. 新hub.db只通过显式维护入口和Alembic空baseline初始化；服务启动不创建/迁移业务库；旧db.py不参与新库管理。Phase0没有提前建立未来业务表。
4. 一次性本机入口换取内存会话，Origin/Host/CSRF校验与同源生产静态资源服务；不上复杂多用户权限。访问凭据只写本地0600文件，URL片段不进请求日志。
5. 因.git受限，采用不含个人数据/密钥的源码版本快照作为临时发布工件，明确不声称有Git提交。未来恢复正常Git后可导入源码，不触碰旧占位目录。
6. 私密功能在加密实现验收前关闭。未来独立加密库需保护正文、真实标题、标签、修订和索引；不能只加密正文却把摘要/标题留在普通SQLite。计划使用经审核的AEAD与密码KDF库，密钥仅解锁期间驻留内存；具体算法/参数/口令遗忘策略在Phase1实现前记录专门设计和测试。没有默认云恢复/后门。
7. 当前ASGI测试与生产构建可以在沙箱完成；真实监听被操作系统权限拒绝，不改成公网地址、不假称已完成浏览器验收。P0-A5真实运行仍需允许loopback的环境复验，Phase1前不得忽略该限制。

## 后续条件

新业务录入前验证全量备份覆盖新增Markdown/资料文件；不是继续用旧SQLite-only工具假装全量备份。独立加密库和解锁机制属于Phase1，不在Phase0临时拼装加密。数据目录迁移、异盘介质、系统服务安装和社区发布不隐式执行。用户的按顺序迭代授权持续有效，例行实现与验证无需重复请求确认。
