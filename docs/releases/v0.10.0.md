## 启动与浏览器/桌面专项

活动根已0009，不用init/升级/重装。旧终端若还运行先Ctrl+C，项目根：

```bash
backend/.venv/bin/python -B -m backend.manage serve --data-root runtime/personal-hub --port 8765
```

打开runtime/personal-hub/config/launch-8765.url中新地址，不分享凭据。当前机器已核对GNOME Terminal、Snap Code、Codex路径及终端/Codex参数帮助，实际GUI仍需你操作；程序目录权限与运行环境变化可能使可用性不同。

- [ ] 设置→项目专业工具，选GNOME Terminal命名并保存；按需登记VS Code/Codex，每类一份；重新读取仍在，无自动打开程序。
- [ ] 项目登记一个可信绝对目录，专业工具中选Terminal→预览；核对目录，关闭预览没有窗口。
- [ ] 再预览→确认，真实桌面终端打开正确目录，后续手动运行自己的命令；刷新记录显示已发起。
- [ ] 在自己的环境测试VS Code打开目录（扩展禁用/信任仍开启），Codex交互打开且没有自动任务，用户自行决定是否使用已配置模型。Hub不读改CLI凭据。
- [ ] 预览后修改项目/停用工具或等60秒，再确认旧预览被拒绝；重新读取并预览才可启动。
- [ ] 模拟程序移动/更新后出现不可用，编辑重新绑定；目录缺失/符号链接明确失败，不生成假成功。
- [ ] 确认后网络结果不确定时先看桌面，保留原预览重试/查记录，不额外开窗；关闭预览不终止已打开程序。
- [ ] 配置草稿、预览和未知请求切换/刷新有保护；错误保留草稿，放弃后重读；亮暗主题/两桌面尺寸/键盘无阻塞。
- [ ] 归档项目不能新启动但历史可查；旧任务、文献、笔记和私密库功能可继续正常使用。

固定GNOME Terminal适配暂不支持其他终端；严格安全权限可能需要核对安装目录；“已发起”不能代替实际桌面验收。API/数据契约见[API](../API_PROJECT_TOOLS.md)、[ADR](../ADR_0010_PROJECT_TOOLS.md)、[操作手册](../OPERATIONS.md)。
