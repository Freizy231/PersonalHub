# v0.11.0：P3-03 饮食规划

2026-11-12。本版按用户“ok，继续”推进功能，外观包装仍后置。版本事实优先于早期规划，前版工具真实GUI不由本版自动推定通过。

## 已实现

- 生活→饮食：每周三餐/食谱/购物清单/冰箱库存四视图。
- 食材名称规范化、查找和重命名；基准份数、步骤、常用食谱、结构化食材用量；普通标签/集合/知识关联/标题与步骤搜索、软回收和恢复。
- 周一至周日，早/中/晚餐同餐多道菜；食谱/份数/日期/备注可编辑，移除不影响原食谱。
- 根据当前菜单和份数生成只读采购预览，展示总需求、当前库存、本周已确认量和缺口；选择→明确追加；之后可手动编辑、标记已买、移除/恢复。
- 手工盘点食材+规范单位的库存绝对余额，可设0。安排菜单/确认采购/勾选已买均不自动扣减/增加库存。
- 首页可选“今日三餐”，默认隐藏；旧布局只投影补新组件，不在GET写盘。支持饮食快捷入口。
- 幂等、CAS、预览摘要、防迟到响应、草稿/导航/刷新保护；普通ZIP与完整v3恢复覆盖饮食数据。

## 已知边界

- 固定单位仅kg/g、l/ml互换，个/份独立；输入小数至多3位，整数运算向上取整，不靠浮点。没有密度推算、营养医学、联网食谱、图片/OCR、库存流水/保质期、自动入库/消耗。
- 库存仅作当前余额对照，不跨周预留。已买仍属于本周已确认量；若又手动把这笔采购计入库存，要人工核对该购物项/库存口径，系统不推断采购流向。高级采购入库事务后续单独设计。
- 食材目录及确认购物项是独立普通数据，隐藏来源食谱不会撤销已经保存的普通购物事实，不在此保存敏感内容。
- 每日≤30道安排、食谱≤100行、食材目录≤10000、每周清单≤2000行（含移除）、预览≤500种食材单位组合。购物有效项UI每20分页；目录/食谱/库存服务端分页。
- 食谱修改影响未来建议；购物行保留确认时数量，不自动同步。菜单移除为软移除，本期无菜单回收站界面；完整导出保留记录。
- 暂未进行本版真实浏览器、两个主题/尺寸、离线桌面人工验收；不自动访问用户项目/真实私密内容。

## 本人浏览器验收清单

启动方式不变（活动升级已完成时无需init/重复升级）：

```bash
backend/.venv/bin/python -B -m backend.manage serve --data-root runtime/personal-hub --port 8765
```

旧实例若仍运行，在它的终端Ctrl+C后重启；只在本机打开config/launch-8765.url里的新地址，不外发入口凭据。

1. 生活→饮食→食谱：先登记“米”“鸡蛋”等虚构食材；创建含0.2kg、2个的常用食谱，设基准2份。重新打开仍保留，重名食材有清晰提示。
2. 每周三餐：同日早餐/午餐/晚餐安排食谱，同餐多道菜；修改份数与备注，查看日期与周导航，无意切换能保草稿。
3. 库存：盘点50克；购物清单→预览，检查份数换算及克/个分开；关闭预览不添加，勾选确认后出现清单。
4. 手改购物数量/备注、标记已买；修改菜单/食谱后清单原项保持；重新预览只建议追加。移除/恢复项目正常，库存始终不自动变化。
5. 另一标签修改同一食谱/购物清单/库存；旧标签保存提示冲突，草稿不丢；临时断开服务后原请求重试不重复创建。
6. 设置→首页布局显式启用今日三餐；只有启用后出现，刷新读取当前日，无复制菜单。重新隐藏后不请求三餐API。
7. 普通资源页标签/集合/关联与搜索定位食谱；回收食谱后菜单隐藏，恢复后重现；完整备份在独立目录恢复（不要覆盖活动根）。
8. 明暗主题、1366×768和1920×1080、键盘Tab、日期/食材选择、空状态、错误提示，断网/Ollama关闭依然可操作。
