# v0.14.1 文献支持 EPUB

2026-11-13。文献模块新增 EPUB 导入、提取、检索与下载。schema 从 `0013_intel_ordering` 升到 `0014_epub_documents`。

## 功能

- **导入**：PDF 与 EPUB 同批上传，单份 100 MiB，单批 20 个文件。格式由文件头字节判定，不看扩展名——把 `.zip` 改名为 `.pdf` 会被识别为 EPUB，改名为 `.epub` 的 GIF 会被拒绝。
- **提取**：EPUB 用内置解析器读取 OPF manifest 与 spine 顺序，提取章节正文与 `dc:title` / `dc:creator` / `dc:subject` / `dc:date`。章节数记入 `page_count`，界面按「章」而非「页」显示。
- **检索**：提取文本进入既有 FTS 索引，与 PDF 同一套可见性与完整性校验。
- **下载**：`GET /documents/{id}/original` 按格式返回 `application/pdf` 或 `application/epub+zip`。
- **导出**：普通 ZIP 导出包含 `.epub` 原件与提取文本。
- **本机阅读器**：EPUB 也可用已登记的阅读器打开（仍为预览 + 确认两步，进度需手动记录）。

## 安全性

EPUB 是压缩包，按不可信输入处理。新增 `backend/app/modules/library/documents/epub.py`，不引入第三方依赖：

| 风险 | 防护 |
|---|---|
| Zip 炸弹 | 条目数 ≤ 5000、单条目 ≤ 8 MiB、总量 ≤ 64 MiB、压缩比 ≤ 200 |
| 路径穿越 | 拒绝绝对路径与 `..`，并校验归一路径仍在包内 |
| XML 实体膨胀 | 任何含 `DOCTYPE` / `ENTITY` 的 XML 直接拒绝 |
| 加密内容 | 检测 zip 加密标志位，报 `password_required`，不猜测解密 |
| 脚本注入 | 提取前剥离 `<script>` / `<style>` / `<head>`，只保留文本 |
| 资源耗尽 | 章节数 ≤ 2000、文本 ≤ 16 MiB，超限失败且不落库 |

提取失败不会写入任何文本或元数据；原文仍可下载。

## 迁移

`0014_epub_documents` 做两件事：补建 `ix_intel_ordering`，并重建 `blobs` 表把 `media_type` 的 CHECK 从只允许 `application/pdf` 放宽到同时允许 `application/epub+zip`。

SQLite 不能原地修改 CHECK 约束，所以采用「建新表 → 按 id 顺序拷贝 → 删旧表 → 改名」。列名、列顺序与全部行值保持不变，升级审计的行摘要比对可以通过。**不新增列**——格式从 `media_type` 推导，因此无需 `ALTER TABLE`，也不会触发 `MIGRATION_DATA_MISMATCH`。

## 未验证

未在真实浏览器中验收；EPUB 渲染不在 Hub 内进行（只做提取与原件下载），实际阅读仍由本机阅读器负责。真实带 DRM 或复杂排版的商业电子书未测试，仅用本地生成的最小 EPUB 样本。

## 升级

需先停止服务：

```bash
backend/.venv/bin/python -B -m backend.manage upgrade --data-root runtime/personal-hub
```

升级会重建 `blobs` 表。升级前会自动生成完整快照，并在副本上先演练。
