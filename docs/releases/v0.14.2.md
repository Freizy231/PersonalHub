# v0.14.2 三餐记录实际菜品、库存可删除

2026-11-14。修三个饮食模块问题。schema 从 `0014_epub_documents` 升到 `0015_meal_dishes`。

## 1. 三餐直接显示吃了什么

以前三餐只关联一个食谱，页面上只看到食谱名，看不出这一餐到底吃什么。现在每餐记录**多道菜**：

- 可以直接手写菜名（「番茄炒蛋」），不需要先建食谱；
- 也可以关联已保存的食谱，两种可混在同一餐里，顺序保留；
- 列表与首页「今日三餐」按顺序显示所有菜名，用顿号分隔。

采购建议的规则随之明确：**只有关联食谱的菜参与食材计算**，手写菜名不产生采购项——手写菜名说明吃什么，不说明要买什么。

## 2. 食谱与三餐计划是两件事

确认了原来的耦合是缺陷：三餐必须有 `recipe_id`，等于把「计划」绑死在「食谱」上。现在：

- `meal_plans.recipe_id` 允许为空，仅作旧数据兼容；
- 菜品存 `meal_dishes`（每行一道菜：要么 `recipe_id`，要么手写 `label`，二者恰好其一）；
- 旧数据升级后自动仍显示原食谱名（升级实测：原有 2 条三餐完整保留）。
- 隐藏规则保留：若一餐引用的食谱被移入回收站或改为私密，该餐不显示也不可操作，避免通过三餐泄露隐藏资料的存在；同一餐里若有手写菜名则照常显示。

## 3. 库存可以删除

库存页每行新增「删除」，物理删除该条盘点记录（它不是派生总额，也没有其他表引用）。带版本校验，过期版本会冲突；同一幂等键重复提交只删一次。删除后 8 秒内可从提示条撤销（撤销按原食材与单位重建该条记录）。

## 迁移

`0015_meal_dishes`：
- 重建 `meal_plans` 把 `recipe_id` 的 NOT NULL 去掉（SQLite 无法原地改，且加列会被升级审计判为数据漂移，因此重建表、列名顺序与行值不变）；
- 新建 `meal_dishes` 表与两个索引。
