# ADR-0018：统一能力接入层与受限 AI 编排

日期：2026-11-18  
状态：已实施（schema `0018_ai_workspace`）

## 背景

旧的 AI 助手是「只读、无工具、无历史、单轮问答」。它证明了一件事可以安全地做，但也把 AI 限定在一个只能解释、不能动手的位置上。本轮需求要求它能在受控范围内创建与组合真实记录。

同时，旧文档中「内置 Agent 冻结」「暂不动 AI 助手」等安排与本轮范围冲突。本 ADR 替代这些条款，并说明替代了什么。

## 决定

### 1. 能力接入层是本轮的核心，不是 AI 本身

模型只产生文本。文本要变成动作，必须依次通过：

1. **注册**：静态能力表（`core/capabilities.py` 的 `CapabilitySpec`），名称、版本、参数、影响、上限、可逆性都在代码里写死。
2. **匹配**：计划里的每一步必须点名一个已注册的能力 ID；未知 ID 直接拒绝，不做「最接近的匹配」。
3. **校验**：参数必须是声明的字段，未声明的字段拒绝而不是忽略；节点必须写验收标准。
4. **授权**：每次写入前检查该学习目标上的授权；读取前检查资源是否在授权子树内。
5. **执行**：交给模块自己的公开服务，业务规则仍在那里。

`core/` 不导入任何业务模块。适配器在 `modules/knowledge/adapters.py`，注册与执行在 `executor.py`。新增能力 = 加一个 spec + 一个函数 + 一个测试，执行器不改。

### 2. 权限是两项，不是一项

- **本地写入**（`local_write`）：绑定一个学习目标，允许在该范围内创建知识点、练习、笔记。不发任何资料出去。
- **外发**（`outbound`）：绑定服务地址 + 模型 + 配置版本，允许把选定资料发送出去。改动配置即失效。

两者分别授予、分别撤销、分别显示。撤销后，下一条写入或外发边界立即停止；已发送的内容无法收回，界面如实说明。

### 3. 计划是草稿，采用是独立动作

模型回复被解析为**草稿**（`ai_plans` + `ai_plan_steps`），解析失败不写任何业务数据。采用是第二次确认，触发一次运行。

计划在写入前写成，所以它引用的是符号（`$path`、`$node0`）而不是真实 UUID——模型没有机会猜错一个 id 并恰好命中别人的记录。采用时由执行器用**本次运行真正创建出来的 id** 去绑定，绑定失败就跳过该步并报告。

### 4. 只有用户发起的操作才调用模型

定时复盘 worker 只计算并记录本地事实（`review`），不调用模型。原因很直接：把资料发到外部服务需要一个人看得见的动作。定时任务可以提醒你「该复盘了」，但不能替你决定内容已经外发。

### 5. 派生内容记录来源版本

`ai_source_refs` 保存每条派生内容所依据资源的版本与哈希。来源被修改后，对话标记为陈旧，不能作为当前依据。来源被隐藏或删除后，只报告 id，不显示标题。

## 替代了哪些旧条款

| 旧条款 | 现在 |
| --- | --- |
| AI 只读、无工具 | 可以调用已注册、已授权、已校验的能力 |
| 无历史、单轮问答 | 支持围绕学习目标的会话；消息正文是受管文件 |
| 每次发送都要预览 | 单次模式保留；另可开启 30 天外发授权，绑定地址与模型 |
| 内置 Agent 冻结 | 本轮放开为受限编排；任意代码自修改、任意命令执行仍不在范围 |
| 不引入事件总线 | 仍不引入：进程内调用 + 持久运行记录 + 有限定时检查 |

## 未做的部分

- 插件市场、热加载代码、通用 shell/SQL 工具、多 Agent 协作。
- 向量检索。当前仍是 FTS5 三元组。
- 多轮对话的模型侧摘要。现在按数量与长度限制上下文，不做自动摘要。
