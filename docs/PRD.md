## 2. 愿景、用户与成功定义

Personal Hub 是 Local-first、Personal-first、Modular 的个人数字生活与工作中枢。每天打开一个入口，安排今天、继续学习和项目、收集信息、积累可以长期导出的知识资产。专业软件负责专业工作，Hub 管理资料、关联上下文和调度入口。

首位且当前唯一用户是计算机专业大学生，研究计算机、网络安全、逆向工程、恶意代码分析与 AI；使用 Ubuntu、GitHub、Codex、Ghidra、IDA、VS Code、终端以及专业阅读和媒体工具。当前不引入用户注册、组织、租户、聊天、关注、社区动态或商业订阅。

核心价值：统一入口、统一管理、资源互通、本地优先、模块扩展、可选 AI、长期知识资产。成功不以堆积功能或打卡时长衡量，以能否完成日常闭环衡量：

| 日常场景 | 完成结果 | 核心验收 |
| --- | --- | --- |
| 早晨安排一天 | 看任务、课程安排、今日三餐，调整学习任务 | 首页完成勾选、改今日计划、快速记录，常用操作不超过 3 次交互 |
| 学习逆向基础 | 路线→知识点→材料→练习→成果→验收 | 能从知识点找到 PDF、笔记、任务和项目；时长不能自动代表掌握 |
| 阅读论文 | 本地导入、去重、检索、继续阅读、记笔记 | 无网络和无模型时全部可用；外部阅读器进度允许手动记录 |
| 做 Malware Analysis Lab | 打开目录、关联文献、记录实验、推进任务 | 不复制项目源码；不在 Hub 执行不可信样本 |
| 技术发现 | 从 GitHub 情报保存资源到稍后阅读，再关联项目 | 保留来源、指标、观察时间；不把热度当质量 |
| 晚间复盘 | 写日记、看输出成果与目标进度 | 私密内容不出现在普通搜索、首页和 AI 上下文中 |
| 管理日常生活 | 菜单变购物清单，记账和运动有统一入口 | 先完成轻量记录或调用已有工具，不重造专业系统 |

## 3. 不可妥协的产品原则（G-01～G-12）

1. Local-first：业务事实优先落本地数据库与文件系统。
2. 核心功能不依赖必须在线的 SaaS；情报刷新可因断网暂停。
3. 核心功能不依赖 AI，AI 关闭或故障不影响 CRUD、搜索、备份。
4. 一级模块有清晰边界，公共能力复用服务，不跨模块直接改表。
5. 模块通过统一资源 ID、标签、集合、项目和显式关系连接。
6. 个人数据可完整导出，保留关联、时间与文件，不锁定于 UI。
7. 代码、用户数据、配置、日志、备份分离。
8. 备份、恢复和恢复演练先于大量录入。
9. 默认不公开个人内容；本地索引也遵守隐私范围。
10. 专业软件负责专业工作，Hub 负责管理和调度。
11. 优先开放格式：Markdown、JSON、PDF、SQLite。
12. 不为功能数量牺牲稳定性；每阶段经数据保护和验收门禁再扩大范围。

## 5. 一级模块与需求规格

优先级 P0=数据安全与阶段门禁；P1=第一版日常闭环；P2=知识与学习；P3=生活/项目扩展；P4=情报/AI 增强；P5=未来选项。优先级不等于所有模块必须同一版本交付。

| DASH-04 | 快速记录、快捷应用启动器、今日三餐、最近活动 | 快速记录先入收件箱；启动专业应用有参数预览与二次确认 |

### 5.2 Life 生活（LIFE-*）

**LIFE-T01 日程与任务（Phase 1）**：Task 状态 `todo→doing→done`，支持取消和重新打开；优先级、分类标签、截止日期/时刻、计划执行日、手动排序、提醒。每日计划引用原任务，不复制任务。Event 支持定时/全天、地点和备注；课程可以先逐条录入。提醒只保证 Hub 服务运行时的站内投递，机器关机不承诺系统通知；重启按补偿规则标记错过提醒。第一版不做双向 CalDAV、复杂重复日程、跨设备同步。

**LIFE-N01 日记与树洞（Phase 1）**：每日记录、随手记、灵感、私密日记、树洞均使用 Note，区别在 `note_kind` 与隐私级别；Markdown、本地文件、标签、全文检索和时间线。普通快速记录默认个人本地；“私密日记/树洞”默认 private。每日日记允许同日多篇，不因日期相同覆盖。树洞是私密自我记录，不提供匿名社区或心理诊断。删除先入回收站；异常保存保留草稿并提供重试，不显示假成功。

**LIFE-M01 饮食（Phase 3）**：三餐与每周菜单、常用菜品、食谱、食材清单、冰箱库存、购物清单。菜单选菜后生成购物清单草稿，用户确认份量和库存后保存；不同计量单位不自动相减。库存允许人工调整，实际消耗不由“计划吃过”自动扣除。不做复杂营养医学、过敏诊断或医疗建议。

**LIFE-A01 本地音乐（已取消）**：用户明确取消全部音乐开发，包含本地目录索引、曲目元数据、收藏、歌单、最近播放及播放器启动适配。该项不再属于开发或验收范围，不以媒体管理名义延续。照片/其他资料原有目录入口规划不因此扩展，不做人脸识别和相册 DAM。

**LIFE-F01 财务（Phase 3，先调查）**：先登记现有账本/工具、格式、币种和导入导出能力。当前项目无财务实现；若外部已有成熟系统，优先快捷入口或只读统计适配。确实没有时才实现手工收支、类别、月预算、分类统计、月报，金额使用最小货币单位整数；多币种不直接求和。无银行同步、投资建议或税务系统。D-05 未决前不开发新记账内核。

**LIFE-E01 运动（Phase 3）**：手动运动/跑步记录，时长、距离、训练计划、训练日历、个人统计；计划引用 Task/Event。区分计划与实际完成；不接可穿戴设备或进行医学评估，配速只在距离与时长有效时计算。

### 5.3 Learning 学习中心（LEARN-01～06，Phase 2）

| ID | 功能 | 必须满足 |
| --- | --- | --- |
| LEARN-01 | 目标、路线、知识树、阶段 | 目标可描述预期成果、目标日和验收标准；知识树第一版为有序父子结构，无环 |
| LEARN-02 | 材料：书籍、论文、课程、网页、笔记 | 引用 Library 资源，不复制另一套文献和书籍数据 |
| LEARN-03 | 学习计划和每日学习任务 | 复用 Task；学习时长手动记录或计时，防止重复计时；修改留痕 |
| LEARN-04 | 实践、实验记录、技术成果 | 练习是 Task，实验是 Note(kind=experiment)，成果是资源关联 |
| LEARN-05 | 掌握与验收 | `未学/接触/练习/已验证`，记录自评、证据、验收时间；只有明确证据和验收结论才能“已验证”，耗时不自动升级 |
| LEARN-06 | 阶段复盘 | 展示目标、实际成果、未解决问题、下一阶段；人工可完整完成，AI 可选 |

示例：路线“恶意代码分析基础”→知识点“PE 导入表”→关联书籍章节/PDF/课程→任务“解析一个安全样本”→实验笔记和仓库提交→按“能解释并复现导入表解析”验收。Phase 2 可以关联仓库网页；Phase 3 再关联正式个人项目。路线完成率=已验收必修节点/必修节点，空路线显示“尚未设置”；可选节点、时长、任务完成率分开，不混成分数。

### 5.4 Projects 个人项目（PROJ-01～04，Phase 3）

项目列表、详情、状态、目标、目录引用、GitHub URL；任务、里程碑、关联文献、实验记录、项目日志、阶段总结。项目进度按必需里程碑/任务口径分别显示，不把 GitHub Star 当个人项目进度。目录是引用，不移动或复制项目文件。

“Malware Analysis Lab”可关联本地目录、GitHub 仓库、论文、Note 实验/日志和 Task；选择批准的启动配置打开 VS Code/Codex/Ghidra/IDA/终端。Hub 不执行或自动分析恶意程序，不接受网页文字或 AI 生成的任意 shell 命令。

### 5.5 Intelligence 情报（INT-01～07）

现有 GitHub 保留可用；Phase 1～3 以兼容入口/只读适配接入。Phase 4 按来源逐个交付：GitHub 适配→RSS/Atom→HN/arXiv→Hugging Face→其余待平台权限评估的 Reddit/Lobsters/Product Hunt。不假设这些平台都有免费、稳定 API。

INT-01 独立 Collector：统一收集契约、来源状态、分页/限流、错误与重试、去重和中断续跑；网页刷新不发起采集。

INT-02 统一记录：平台稳定 ID、原 URL/规范化 URL、标题、作者、时间、类型、领域、原始公开载荷及原始指标。旧历史没有原始 JSON，必须标记缺失，不能从现有字段伪造。

INT-03 历史与趋势：每次有效观察保留快照；原始 Star/Fork/score/votes/downloads 等带时间、单位和统计窗口。平台内排名，跨平台只按相关性/时间分组；不简单相加不同平台指标。未来标准化指标须可解释、带算法版本，不能混同原始事实。

INT-04 去重：同来源稳定 ID 幂等；URL 规范化保守去掉已知追踪参数，不删除语义参数；跨平台同链接建立“同一目标”关系，保留每个平台记录和热度。模糊标题只提示人工确认。

INT-05 领域筛选、字面关键词订阅、稍后阅读、收藏集合；订阅命中去重，关闭订阅保留历史。

INT-06 周报：周期、来源覆盖、实际观察窗口、质量告警、收藏/稍后读条目；人工模板汇总可用，AI 仅辅助草拟，不默认外发或发布。

INT-07 回归：保留现有 GitHub 稳定 ID、历史不足/零基线/负增长/过期语义；现有周增长 7～8 天观察跨度、最新≤48h 不变。Open Issues 包含 PR，必须标注。

### 5.6 Library 知识库（LIB-01～07，Phase 2）

| ID | 功能与流程 | 边界/验收 |
| --- | --- | --- |
| LIB-01 | 单/多 PDF 上传→暂存→验证→流式 SHA-256→去重→入库→异步提取 | 同批/跨批去重，重复显示已有资源并可补标签；每文件独立结果，失败不阻塞其他文件 |
| LIB-02 | 本地 PDF、元数据/文本提取、分类、标签、个人备注、全文搜索 | PyMuPDF；提取失败仍可管理原文件；加密 PDF 标记需密码，密码不持久化；扫描版提示无文本，OCR 后续 |
| LIB-03 | 阅读状态、页码进度、书签、外部阅读器 | 页码显示 1-based；外部软件进度默认人工更新；高亮/批注导入导出和内置高级阅读器后续 |
| LIB-04 | 书名、作者、分类、进度、笔记、评分、关联 | Book 是独立书目，可关联一个或多个 PDF/电子版，不把实体书强制成文件 |
| LIB-05 | 网页 URL、标题、摘要、标签、收藏时间、阅读状态 | 第一版手工保存元数据；正文快照 Phase 4 后另行评估版权/SSRF/大小限制 |
| LIB-06 | Markdown 创建/编辑/删除，本地文件、双向链接 | `hub://resource/<UUID>` 为稳定链接；标题变化不破坏关系；外部编辑冲突不静默覆盖 |
| LIB-07 | 文献/书籍/笔记/任务/项目互联、全局搜索 | 从详情可看相关资源与反向链接；私密范围不进入普通搜索和建议 |

初始上传上限建议 100 MiB/文件、20 文件/批，作为可配置设计默认；需 Phase 2 在本机大 PDF 样本验证后定版。默认复制托管到本地资料库，用户原文件保持原状。PDF 备注使用关联 Note，不嵌入 PDF 修改源文件。分类第一版使用单层 Collection(kind=category)，其余主题用 Tag。

### 5.7 AI Assistant（AI-01～05，Phase 4）

AI-01 默认关闭，优先本机 Ollama，模型安装由用户选择，不自动下载；不可用时显示配置/重试和非 AI 操作入口。

AI-02 本地文档问答、PDF 总结、笔记检索、学习复盘、每周总结、情报整理、学习/饮食建议与资料搜索。先做用户选定资源的总结和检索，再做 RAG；回答附资源/页码/片段引用与无法确定的说明。

AI-03 默认只读，建议写入先形成草稿，用户确认目标和内容后保存。删除、覆盖、启动命令等高风险动作必须再次确认；第一期不提供 AI 命令执行工具，后续 Agent 单独评审。

AI-04 私密资料默认排除于检索、摘要、向量索引、历史和遥测。用户即使选择本地模型也需本次明确选入私密内容；不自动外发第三方 API。外部模型不在当前实施范围。

AI-05 不自动改掌握程度、不自动完成任务、不自动发布周报；文档中的提示词不是工具权限，所有调用在服务端重新校验。

### 5.8 Settings（SET-01～06）

基础设置、时区（初始建议 Asia/Shanghai，用户可改）、亮暗主题、布局、数据目录和文件目录；数据库状态/版本/只读诊断；备份/恢复/完整导出；Ollama 与外部应用配置；Token 仅显示是否配置、不回显原值；定时任务、脱敏日志和隐私策略。

恢复需预览备份内容、版本、完整性与影响范围，二次确认后停写并恢复；路径变更需可写性/空间检查、迁移预览、校验与回退；不能只修改配置导致“旧数据消失”。第一版不提供任意 SQL 控制台，不在设置页自动运行迁移。

## 7. 非功能要求与可验收质量

- 离线：断开网络并关闭 Ollama 后，任务/日历/日记/本地资料/搜索/备份均可用；离线状态清楚区分“无法刷新”与“没有数据”。
- 数据：断电/任务中断不丢已提交内容；文件与数据库不一致可被诊断和修复；恢复演练验证关联和校验值，不只验证能打开数据库。
- 性能目标：参考 4 核 CPU、16 GiB 内存、SSD 的 Ubuntu；10,000 资源/10,000 任务、1,000 份已提取 PDF 作为 Phase 2 种子规模。首页缓存后 p95≤2s；任务写入 p95≤500ms；普通关键词搜索 p95≤1s（私密范围过滤后，前 50 条）；导入/提取不阻塞交互。Phase 0 记录真实机器，若不达标先分析再调整目标。
- 测量：本机浏览器和 API 分别记录 20 次预热后至少 100 次交互的 p95；PDF 提取按文件大小/页数独立报告，不把模型推理纳入首页指标；不上传监控。
- 可用性：主要操作可键盘完成、错误不丢草稿、页面显示保存/失败/冲突/离线状态；空值不假装为零。
- 可维护性：模块化单体；每阶段可独立发布和回退；文档和迁移随功能更新。
- 可移植性：完整导出包含数据库、Markdown、托管文件、资源 ID/关系和清单；有恢复与重新索引路径；密钥单独处理。

生活→饮食提供食材目录、常用食谱、每周早中晚多道安排、采购对照预览→选择确认→独立清单→实际库存盘点的完整链路。专业营养/AI/联网食谱不在范围。食谱为统一Resource，公共标签/集合/知识关联及搜索复用既有服务；其他食材、菜单、购物、库存为独立业务实体，避免把一切塞入Resource。

完成目标：能创建基准2份食谱并安排1或多份，克/千克和毫升/升精确换算，个/份保持独立；购物预览列明需求、库存、本周已确认、缺口。用户明确确认后清单成为普通人工事实，菜单变化永不自动覆盖；已买不自动入库，计划不扣库存。库存盘点为明确绝对余额含0，CAS防旧值覆盖。当前余额不跨周预留，已买也属于已确认量，手动计入库存后需人工核对清单口径。

首页今日三餐默认隐藏，只读取实际菜单。食谱/目录/库存分页，空状态引导先登记食材，允许无食材食谱表达外食。保存失败保留草稿，结果不确定只能原请求重试；预览失效须重新核对。容量/数量边界、完整验收及未实现项见[API](API_DIET.md)与[v0.11](releases/v0.11.0.md)。本版普通记录不适合敏感饮食/医疗数据；真正私密内容仍进入vault。本地音乐需求已取消，下一P3-05财务现有工具调查；视觉整合继续后置。

## v0.12 功能范围与验收边界

用户新决定D-05：没有现成财务软件，实施Hub本地轻量账本；D-07改为API接口，不部署本地模型，服务商/endpoint/model/凭据待本人在本机设置。无需在聊天中提供密钥。最新授权为持续功能开发，美化前统一验收，覆盖早期逐小版本等待指令。

本版Local-first指业务与原件离线可用、由用户控制外部传输，不再等于“永不连接API”。用户明确选择问题与资料发送，不是对全部个人数据的上传授权。Privacy-first不以模糊文案暗示明文账本已加密。

功能包装仍待统一搜索/日期左侧入口、资料库聚合、博客式笔记与Obsidian协作、密度与快捷键体验；按用户要求在此之前暂停，先由本人功能验收。P4-05向量检索仅评估门禁，不为追求“全完成”下载模型；高亮批注/全文网页快照/移动端/社区仍按原后续规划，不混入本轮。
